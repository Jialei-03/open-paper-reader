# 加大样本：预注册（2026-10-20 08:00）

全新封存集和事后复查都表明：每格 5 个种子时，同一任务、同样条件的两次运行，平均轮数能相差将近一轮，和要测的效果一样大。这一次在一个任务上加大样本，在跑之前写下要检验什么。

## 设置

- 任务：`fresh-fraud-leak`（标签泄漏，新任务）。
- 条件：学到的手册、不读手册，各 15 次（种子编号 101 到 115，和之前的运行不重叠）。
- 代码：main 的 `58b8e54`，包含评测方式的修正。两个本机服务运行的是同样的代码。学到的手册与之前相同。
- 分析：`scripts/research_eval/compare.py`，报告两个条件平均轮数之差、平均 token 之差，以及 95% 自助法（bootstrap）置信区间（10000 次重抽样，固定种子 0）。

## 要检验的

**主要问题**：学到的手册能不能减少泄漏任务的平均轮数？

- 平均轮数之差（手册减不读手册）的 95% 置信区间整个小于 0，就算"有作用"；
- 区间包含 0，就算"没有检测到作用"。

次要指标：token 之差，以及满分次数。

无论结果如何都如实报告，结论只依据上面写好的规则。
