# 性能与思考强度

需要模型的固定功能（翻译、导读、测验、目录、重点建议、图表识别）不是对话，不需要长时间思考。Open Paper Reader 按功能选择思考强度，而不是一律沿用对话里的设置。本文记录这个选择的依据：一次针对真实模型的测量，以及它的局限。

## 怎么测的

[`scripts/bench_model.py`](../scripts/bench_model.py) 在临时数据库和临时目录里，用和产品相同的代码路径（HTTP 接口、助手 worker 子进程、翻译引擎、TeX 编译）调用真实模型，不碰你的数据，也不输出密钥。

```bash
PLATFORM_MODEL_CONFIG=data/platform-model.json BENCH_DIR=/tmp/paper-bench \
  .venv/bin/python scripts/bench_model.py pages --pages 1,2 --model platform-minimax
```

- 模型来自 `PLATFORM_MODEL_CONFIG`（格式见 [配置](CONFIGURATION.md#共享模型文件)；`scripts/set-local-model.sh` 可以交互式生成）。`--model` 是共享模型文件里模型的 `id`，主模型的 `id` 固定为 `platform-minimax`（沿用最初的名字，与厂商无关）。
- 场景：`pages`、`selection`、`region`、`guide`、`quiz`、`outline`、`highlights`、`latex`、`figures`、`probe`；结果打印出来，并追加到 `BENCH_DIR/results.jsonl`。
- 默认取一篇 28 页的 arXiv 论文（`--arxiv` 或 `--pdf` 可以换）；秒数是从提交到结束的整段时间，包含助手子进程启动（约 1–2 秒）。
- `BENCH_PASSWORD` 可以指定临时账户的密码，不设置时由临时目录推导；这个账户只存在于一次性的数据库里。

## 数据

下面是一次测量的结果，用的是 MiniMax-M3.1-Flash-Preview 和一篇 28 页论文。每格只有 1–4 次样本，网络和上游负载会波动，请看量级和趋势，不要在意个位数秒的差别。

对照翻译、划选翻译和 LaTeX 整篇翻译，是**同一个模型在固定任务里改用低强度与直接调用前后**的对比：

| 功能 | 对话式的逐页任务、模型默认强度 | 固定调用、低强度 |
| --- | --- | --- |
| 对照翻译，整篇 28 页 | 逐页串行，每页 13–18 秒，共约 6–8 分钟 | 3 页一批并行，**约 135 秒**，输入 token 约为原来的 1/10 |
| 划选「AI 精译」 | 7.9–10.5 秒（2 次请求） | **2.6–3.1 秒**（1 次请求） |
| 框选区域翻译 | 7.3–11.3 秒 | **3.4–4.9 秒** |
| LaTeX 整篇翻译（106 段） | 201.6 秒，输出 62.9K token | **48–52 秒**，输出 20K token；编译 11–30 秒 |
| 论文导读 | 44.7–137.9 秒 | **17.7 秒**（中强度 37 秒，模型默认 153 秒） |
| 阅读测验 | 18.9–42 秒 | **16 秒**（中强度 17 秒，默认 38.5 秒） |

同一页翻译，仅改变思考强度（M3.1 必须思考，不指定强度时思考得很久）：

| 强度 | 每页耗时 | 输出 token |
| --- | --- | --- |
| 低 | 9–10 秒 | 1.4–1.6K |
| 高 | 11–42 秒 | 1.8–3.3K |
| 默认（不指定） | 35–104 秒 | 4.5–11.6K |

## 由此得到的规则

- **翻译、目录、重点建议、图表识别、连接测试**：固定用最低强度，不随你给对话设置的强度变化。翻译请求在界面上不显示「思考强度」，因为它由系统决定。
- **导读、测验**：你没有选强度时用低（实测质量够用，速度快 2–9 倍）；你选了什么就用什么。
- **对话、解释**：你没有选时用中；选了就用你的。
- 参数未知的自定义模型一律沿用你的设置，不会冒险发送它可能不认识的字段。

## 测量时发现并修复的问题

1. **重点建议**：模型给出的引用必须逐条按原文先后排序，否则整批作废。现在只保留能在原文里核实的引用，按原文顺序排好，不能核实或重复的去掉，一条都不能核实才失败。
2. **导读被截断**：助手运行时每次模型调用最多输出 8192 token，而 M3.1 的思考和回答共用这个额度，长 JSON 会被截断。现在 MiniMax 系列用 32768，三句摘要被挤成一条时按句号拆开。
3. **整篇对照翻译有页失败**：模型会「纠正」论文原文（conduct→conducted）、缩短目录页的点线、按版面顺序而不是文字层顺序排条目。现在原文与页面文字差异很小时以页面文字为准（阈值 93%，改一个词仍然会被拒绝）；表格和目录页允许按读者顺序排列，但每段仍须在页面上、合起来仍须覆盖 95% 以上；提示词要求逐字照抄。28 页的论文从 2 页失败降到连续两次 0 失败。
4. **目录偶发「没读全」**：让模型自己翻页读 28 页并不可靠。目录、导读、测验、重点建议改成服务端读全文、一次调用，检查不通过再纠正一次；扫描页或超过 60 页的论文仍走助手。
5. **瞬时的 HTTP 错误**：直接调用遇到 408/422/425/429/5xx 会等 1.5 秒后重试一次。
6. **批次大小**：对 M3.1 试过更大的批次（6 次请求 52 秒），并不比小批次（22 次请求 46 秒）快，所以保持原来的策略。

## 局限

- 只测了一篇英文论文（有表格和公式）；没有测扫描版 PDF，也没有测超过 60 页的论文（它们走助手，速度和可靠性沿用对话式的路径）。
- 完整对比只在一个模型上做过，其他服务商的模型没有测。
- 页面翻译大约 2% 的页面仍可能因为模型改写过多而失败：重试一次后仍失败会明确提示，已完成的页保留。
