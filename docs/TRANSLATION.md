# 翻译

Open Paper Reader 有四条翻译路径，针对不同的需求。原 PDF 始终保持不变，译文是同一版本下的派生内容。

| 路径 | 用途 | 需要 |
| --- | --- | --- |
| 对照翻译 | 逐页、逐句读译文，悬停联动原文 | 模型 + 助手 worker |
| 选段 / 框选翻译 | 选中一段话、框住一个表格，马上看译文 | 选段快译无需模型；AI 精译需要模型 + worker |
| 整篇翻译（LaTeX 源码） | 提供源码的 arXiv 论文 → 排版完整的中文 PDF | 模型 + 翻译 worker + TeX 镜像（Docker） |
| 版面翻译（普通 PDF） | 没有源码的 PDF → 重新排版的中文 PDF | 模型 + 翻译 worker + 版面镜像（Docker），实验性 |

部署方式见 [部署](DEPLOYMENT.md#可选组件)，环境变量见 [配置](CONFIGURATION.md#翻译)。

## 对照翻译

阅读器里打开「翻译 → 打开对照」。逐页提交给模型，译文按句子成对返回，悬停一句译文时原文里对应的句子亮起；可以调整分栏、译文字号、翻译剩余页面，也可以重新翻译某一页。

- 译文以页面文字层为准：服务端校验模型返回的每一句「原文」确实出自该页的文字，不一致的会被拒绝或对齐回页面文字，所以高亮定位到的是论文真实的句子，不是模型改写后的句子。校验失败的页明确提示，已完成的页保留。
- 翻译是固定任务，不需要长时间思考，所以对已知的模型使用最低的思考强度，不随你给对话设置的强度变化。实测数据见 [性能](PERFORMANCE.md)。
- 整篇按几页一批并行请求，一篇 28 页的论文在实测中约两分钟。多个账户共用同一个共享模型时受 `PLATFORM_MODEL_CONCURRENCY` 控制。
- 没有文字层的扫描页不能逐页翻译；用框选翻译，模型能识图时会连图片一起看。

## 选段与框选翻译

选中文字点「翻译」，立即显示 Google 翻译的结果；需要更准的译法点「用 AI 精译」，由你选的模型翻译，结果和原文一起保存在翻译面板。框选表格或图表后点「翻译选区文字」读取框内的文字（行列结构保留为 Markdown 表格）。

> **隐私**：「快译」会把选中的文字发送到 `translate.googleapis.com`。如果你的论文不能离开你的服务器，请在出口防火墙上拦掉这个域名（快译会提示失败，AI 精译不受影响），或只使用 AI 精译。

## 整篇翻译（LaTeX 源码）

对提供 LaTeX 源码的 arXiv 论文：下载源码，翻译正文，保留公式、图表和排版，重新编译成中文 PDF。

1. 解析源码，把公式、引用、标签等换成不可变的占位符（解析与重建部分改编自 [LaTeXTrans](https://github.com/NiuTrans/LaTeXTrans)，MIT，改动见 `backend/vendor/latextrans/NOTICE.md`）。
2. 模型只收到带占位符的文字片段；返回后校验占位符是否完整、数量是否一致、LaTeX 结构的顺序是否保持。不通过的片段不会进入译文。
3. 在一次性的 TeX 容器里编译：无网络、只读根目录、没有 shell escape、非 root、有内存/CPU/进程/时间上限，只挂载这一次的源码项目，不挂载任何密钥。缺字或编译失败不发布 PDF，也不会生成空的「成功」译本。
4. 已完成的片段会原子保存为检查点；服务正常停止后重启会恢复进行中的任务。同一篇论文同时最多一个活动任务。

限制：只支持提供源码的 arXiv 论文；源码解析是受限范围内的兼容实现，不保证所有模板都能成功；图片内部的文字和受保护的表格、算法保留原文。中文字体用 `fontspec` 的 `no-math` 选项，保留论文自己的数学字体。

## 版面翻译（普通 PDF，实验性）

没有源码的 PDF，用 [BabelDOC](https://github.com/funstory-ai/BabelDOC) 识别版面、保护公式与样式、翻译正文并重新排版。它运行在独立镜像里（构建时下载版面模型和字体，运行时无网络，内存上限 1400 MiB），模型请求由父进程代理，API 密钥不会传给子进程。

产物发布前逐段核验：漏译、公式或样式标记不一致、代码里的常量被翻译（例如 `UPDATE` 变成「更新」）都会被拒绝。**质量因论文而异**：一次 23 页论文的真实运行用了约 21 分钟、75 次模型请求；图内的英文保留，重复页眉的译法可能不一致；扫描件 OCR 与公式密集的页面没有验收。BabelDOC 采用 AGPL-3.0，见 [NOTICE](NOTICE.md)。

## 模型与费用

翻译会把论文正文发送给你选择的模型服务，按那个服务的计费。「设置 → 模型」里的测试只发一个短请求；只有启动翻译才会发送论文内容。设置里可以查看用量，并可以用 `SHARED_MODEL_DAILY_TOKENS`、`PRIVATE_MODEL_DAILY_TOKENS` 给每个账户设每日预算。

## 运维要点

- 翻译 worker 是单独进程（`python -m backend.translation_worker`），用文件锁保证只有一个；每个账户最多 3 个活跃翻译任务。
- 中间文件按 `TRANSLATION_CACHE_DAYS`、`TRANSLATION_ORPHAN_DAYS` 清理；失败、取消和进行中的任务检查点不会被清理。
- 下载 arXiv 慢或被拦时设置 `ARXIV_PROXY`（只用于 arXiv）。连接中断、超时和暂时性错误会重试，仍失败时给出明确提示。
- 备份前先停 worker 再停网站；恢复到新主机后需要重新填写模型密钥（见 [运维恢复](OPERATIONS-RECOVERY.md)）。
