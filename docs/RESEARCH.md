# 研究

研究功能让 Agent 在你自己的电脑上推进研究问题：和你对话定下计划，在本机或远程 GPU 上做真实实验，由独立的导师守住方向，关键的决定由你来做，结论都有据可查。本页说明怎么用、每个部分做什么，以及评测怎么跑。代码层面的说明见 [开发手册](DEVELOPMENT.md#研究系统)。

## 准备

1. 运行本机版（见 [本机版](LOCAL.md)），在「设置 → 模型」里添加一个模型。
2. 在「设置 → 研究环境」里准备实验环境。有两种：

   | 环境 | 说明 |
   | --- | --- |
   | **本机**（默认） | 实验直接在这台电脑上运行，不经过容器，能用 Apple 芯片的 GPU（MPS）或 NVIDIA 显卡。没有隔离：Agent 写的代码以你的身份运行。 |
   | **SSH 机器** | 实验室服务器、带 GPU 的 WSL 等。主机用 `~/.ssh/config` 里的名字或 `user@host`，以非交互方式登录，系统不保存密码；远端需要 Python 3 和 rsync。 |

   本机和 SSH 环境由一个 Agent 来准备：点「让 Agent 准备」，说明需要什么（默认是匹配显卡的 PyTorch 和常用科学计算包），它会查看这台机器，装好需要的东西，然后调用 `finish_setup` 报告用哪个 Python。系统会自己用这个 Python 检测一遍，PyTorch 能导入、配置了 GPU 时也看得到 GPU，才标为「就绪」。准备过程可以在窗口里实时看。本机环境装在数据目录的 `research/host-setup/` 下的独立虚拟环境里，不动系统的 Python，也不用 sudo；SSH 环境可以允许 sudo。

3. 想把实验同步到 SwanLab 或 Weights & Biases，在「设置 → 实验追踪」里选择，并安装可选依赖 `pip install '.[tracking]'`。API 密钥只存在本机的设置文件里，不会返回给浏览器，也不会进入实验。

## 项目

研究按项目组织。首页和「研究」都会列出你的项目和它们等你决定的事。

- **看板**：每个研究、它的假设和实验，按「想法、待办、进行中、等你、完成、放弃」排在列上。列的位置由研究本身的状态决定；你自己记的想法可以拖动，也可以一键「开始研究」。
- **对话**：项目里可以开多个对话，随时问「进展怎么样」「ResNet 跑到哪了」。对话里的助手能读项目里的一切（研究地图、每一轮的交接、实验和指标、日志），但只读：不能改动或启动任何东西，也不会唤醒研究里的 Agent。
- **研究**：项目里的全部研究，以及开一个新研究的入口。
- **项目资料**：项目说明会写进这个项目里每个 Agent 的简报（比如「只用公开数据」）。项目还可以设置默认的模型和研究环境。

## 一个研究怎么走

研究分阶段推进，每次切换都记录在案：定题 → 实验 → 结论 → 复盘 → 完成。

1. **定题**：用一句话开头。导师和你对话，先回应、再追问基线和限制，必要时查文献，然后用 `propose_plan` 在对话里写出一张计划卡片：问题、指标、基线、目标、若干假设（每个都有止损条件 `kill_if`、价值和代价，排在第一个的是先做的），以及数据集、研究环境和预算。你每提一次修改，就出一个新版本。环境还没准备好时，卡片上会提醒。你点「按这个计划开始实验」，假设才写进研究地图，数据集才开始下载。
2. **实验**：执行者和导师一轮一轮推进（见下文）。你随时可以在研究页里插话，导师下一轮会先回应你。只想问问进展、不想打扰研究，就去项目的「对话」里问。
3. **结论**：导师认为证据足够时提出结论，但要你接受才算数；你也可以要求补做，项目回到实验阶段，你的意见写进之后的简报。
4. **复盘**：提炼者把这个项目的经验写进研究手册（见下文），然后项目完成。

预算默认不设上限。设了上限、用完时，导师会问你要不要追加，而不是直接结束。「暂停」会中止正在进行的一轮并停掉运行中的实验（日志会写明原因），「继续」从地图接着做；「停止」结束研究。

## 它怎么推进

- **研究地图**：北极星问题是根，下面是子问题、假设、实验和发现。每个节点有状态、置信度、支持和反对的证据、疑点和花费。每次修改都记录谁改的、在哪一轮、为什么。
- **轮次**：每一轮从地图、上一轮的交接、导师最新的意见和你说过的话开始，不带聊天历史。一轮结束时，执行者写交接：做了什么、得到什么、下一步推进什么。
- **先聚焦再动手**：运行代码、读写文件、改地图之前，执行者必须用 `focus` 声明正在推进哪个节点。没声明，或者那条分支已被否定，动作会被拒绝并记为一次「硬偏离」。
- **止损条件**：结果满足假设的 `kill_if` 时，假设被否定。
- **实验**：要记录的结果一律用作业（`run_job`）跑。几分钟内能跑完的，执行者等它结束、直接拿到日志；更长的，执行者结束本轮，作业结束后自动开始下一轮。停掉自己的作业用 `stop_job`。在本机环境里，按名字结束进程（`pkill`、`killall`、`kill $(pgrep …)`）会被拒绝，因为它会误伤你电脑上的其他程序。
- **证据**：结果只能引用作业日志里的行，或论文里的原句；结果中的数字必须逐字出现在证据里。作业结束时，系统还会把它的退出码和指标自动记到对应节点上（`run_result`），导师和执行者的简报里直接列出每个作业量到了什么。

## 导师

导师只读：能读地图、作业日志和文献，不能运行代码，也不能改地图。它在这些时候出现：每 3 个执行轮；出现止损信号或执行者声称得到了发现；预算用到一半和八成；连续两轮没有进展；你说了话。

对每个开放的节点，导师给出继续、加注、放弃、转向（必须提出新的假设和止损条件）或请你拍板。它也会逐轮判断执行者有没有偏离北极星问题（「软偏离」）。有只有你知道答案的问题（指标的口径、能接受的代价），它会用 `ask_researcher` 问你，问题出现在对话里，研究不会因此停下。缺少只有你能提供的东西（数据、权限）时，研究停下来等你。

## 数据、实验记录和报告指标

- 公开数据集由系统在后台下载（目前有 MNIST 和 CIFAR-10），每个文件按发布方的校验值核对；有多个镜像时先各试两秒、用最快的。下载进度显示在研究页上。你上传的文件放在工作区的 `data/` 下，也会记下 sha256。
- 实验脚本用 `import ora` 报告超参和指标，这个模块只依赖标准库，每个环境里都能直接导入：

  ```python
  import ora
  ora.config({"lr": 1e-3, "epochs": 5, "seed": 0, "tag": "baseline-s0"})
  ora.log({"train_loss": loss, "val_acc": acc}, step=epoch)
  ora.summary({"test_acc": final})
  ```

  每次调用都在作业日志里打一行（`ORA_SUMMARY ...`），研究结论引用的就是这一行。文件写进只属于这个作业的目录（`ORA_RUN_DIR`），由系统收回。本机直接运行时，实验和 Agent 之间没有隔离。
- 每个作业记录在哪个环境运行、命令、退出码、超参、最终指标和曲线点数；每个环境第一次运行时自动检测 Python、系统、CPU、内存、GPU 和主要包的版本。

## 研究报告

研究页的「下载报告」把记录整理成一份 Markdown：研究问题、结论、每条结果及其引用的日志行或原文、放弃的方向和止损条件、导师的关键判断，以及花费。报告完全从记录生成，不调用模型。

## 研究手册

研究结束后，提炼者读这个研究的完整记录，把经验写成「在什么情况下，怎么做，为什么」的判断规则，并对已经生效的规则投票。

- 规则一开始是「待验证」，被第二个研究支持、或者你在「设置 → 研究手册」里批准后才生效。
- 生效的规则写进之后每个研究的简报，最多 12 条，按有用程度排序。被判有害的次数比有用多 2 次以上的规则自动退役；手册最多保留 40 条。
- 手册存在数据目录的 `research/playbook.json`，带版本和修改历史。

## 过程指标

研究页上的指标都从记录中计算：偏离率（以及未聚焦就动手被拦下的次数）、回头延迟（从出现止损信号到放弃这个假设隔了几轮）、正常交接的比例、证据条数、每条已支持结论的花费。

## 评测

`scripts/research_eval/` 是评测框架：

- `tasks/<name>/`：任务说明（`task.json`）、数据生成脚本（`make_data.py`，固定随机种子）和评分标准。
- 「学习集」的项目会提炼进研究手册，「封存集」的永远不参与提炼，只用来评测。
- 评分只看客观标准：是否记录了证据、是否得出结论、结论的方向、导师是否判定没有偏离、关键数字是否与事先算好的真值一致、缺数据时是否如实报告。执行者、导师和提炼者都看不到这些标准。
- 封存集有五个任务：`imbalance-threshold`（找最优阈值）、`missing-transfer`（缺数据，应如实报告并停下）、`poly-dead-end`（诱人的方向其实无效）、`leaky-feature`（接近完美的准确率来自标签泄漏）、`confounded-treatment`（辛普森悖论）。
- 评测运行没有人可问，所以跳过定题，结论按提出的直接生效。规则改了以后，`rescore.py` 可以给已结束的运行重新打分。

```bash
python scripts/research_eval/run.py --tasks imbalance-threshold missing-transfer \
    --condition playbook --seeds 2 --max-sprints 8 \
    --data <数据目录> --model <模型配置编号> --out scripts/research_eval/results/<名字>.jsonl
python scripts/research_eval/report.py scripts/research_eval/results/*.jsonl
```

可比较的条件：`playbook`（读研究手册）、`no-playbook`（不读）、`no-advisor`（没有导师）。
