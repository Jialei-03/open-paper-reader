# 研究

研究功能让 Agent 在你自己的电脑上推进一个研究问题：维护研究地图、按轮推进、在隔离环境里跑实验，由独立的导师判断方向，并把经验沉淀进研究手册。本页说明怎么用、每个部分做什么，以及评测怎么跑。

## 准备

1. 本机版（见 [本机版](LOCAL.md)），并在设置里添加一个模型。
2. Docker，以及一次性构建实验环境：

   ```bash
   make research-image
   ```

   镜像里有 Python 3、numpy、scipy、pandas、scikit-learn、matplotlib 和 CPU 版 torch。实验环境没有网络，需要的数据要放进项目。
3. 在 macOS 上用 colima 时，Docker 默认只能看到主目录。数据目录默认在 `~/.open-paper-reader/`，不用额外设置；放在别处时，要把那个目录加进 colima 的挂载。挂载不对时，研究页会说明"实验环境看不到项目工作区"，而不是让 Agent 看到一个空目录。

## 开始一个研究

在「研究」页新建：

- **研究问题**：一句话写清要回答什么。Agent 会一直围绕它推进，这就是"北极星问题"。
- **背景**：已知情况、数据在哪、约束条件。背景是资料，不是指令。
- **数据文件**：放进 `/work/data/`，实验里直接读取。也可以之后在项目页添加。
- **模型**和**最多轮数**。

创建后，第一轮马上开始。项目页可以随时暂停、继续或停止；停止时，正在运行的实验也会被终止。

## 它怎么推进

- **研究地图**：北极星问题是根，下面是子问题（question）、假设（hypothesis）、实验（experiment）和发现（finding）。每个节点有状态、置信度、支持和反对的证据、疑点和花费。每次修改都会记录是谁改的、在哪一轮、为什么。
- **轮次**：每一轮从地图、上一轮的交接和导师最新的意见开始，不带聊天历史。一轮结束时，执行者写交接：做了什么、得到什么、下一步推进什么。
- **先聚焦再动手**：运行代码、读写文件、改地图之前，执行者必须用 `focus` 声明正在推进哪个节点。没声明，或者那条分支已被否定，动作会被拒绝并记为一次"硬偏离"。
- **止损条件**：每个假设都必须写 `kill_if`：出现什么结果，就说明这条路不通。记录结果时，执行者要对照它判断是否触发；触发后，假设被否定。
- **实验**：几十秒内能跑完的命令直接运行；更长的实验用后台作业。启动作业后，执行者结束本轮，作业结束后下一轮自动开始。作业的输出由系统保存在工作区之外。
- **证据**：结果只能引用作业日志里的行，或论文里的原句。结果中的数字必须逐字出现在所引的证据里；问题和背景里已经给出的设定（比如测试集比例）除外。没有记录过证据的节点，不能标为"已支持"。

## 导师

导师是一个只读的角色：它能读地图、作业日志和文献，不能运行代码，也不能改地图。它在这些时候出现：

- 每 3 个执行轮；
- 出现止损信号，或者执行者声称得到了发现；
- 预算用到一半和八成；
- 连续两轮地图没有任何进展。

对每个开放的节点，导师给出继续、加注、放弃、转向（必须提出新的假设和止损条件），或者请你拍板。判断直接生效。它还会逐轮判断执行者有没有偏离北极星问题（"软偏离"），并评估这条研究线值不值得做。北极星问题已经有记录在案的证据可以回答时，导师结束项目。

请你拍板时，项目进入"等你拍板"。在项目页同意，导师的提议就会生效；不同意，节点保持原样。你写的话会带给下一轮。

## 研究手册

项目结束后，一个"提炼者"会读这个项目的完整记录：导师的判断、止损、偏离、交接和过程指标。它把经验写成"在什么情况下，怎么做，为什么"的判断规则，并对本项目开始时已经生效的规则投票，判断它们有用还是有害。

- 规则一开始是"待验证"状态。被第二个项目支持，或者你在研究页批准后，才"生效"。
- 生效的规则会写进之后每个项目给执行者和导师看的材料里，最多 12 条，按有用程度排序。
- 被判有害的次数比有用多 2 次以上的规则，会自动退役。手册最多保留 40 条。
- 手册存在数据目录的 `research/playbook.json`，带版本和修改历史。

## 过程指标

项目页上的指标都从记录中计算：

- **偏离率**：导师判定偏离北极星问题的执行轮占比。另外记录未聚焦就动手被拦下的次数。
- **回头延迟**：从出现止损信号，到放弃这个假设，平均隔了几轮。
- **正常交接**：执行者正常写了交接的轮次占比。
- **证据条数**：地图上引用的日志段和原文句子。
- **每条已支持结论的花费**。

## 评测

`scripts/research_eval/` 是评测框架：

- `tasks/<name>/`：任务说明（`task.json`）、数据生成脚本（`make_data.py`，固定随机种子）和评分标准。
- 任务分为两类。"学习集"的项目会提炼进研究手册；"封存集"的项目永远不参与提炼，只用来评测。
- 评分只看客观标准：是否记录了证据、是否得出结论、导师是否判定没有偏离、关键数字是否与事先算好的真值一致、缺数据时是否如实报告。这些标准执行者、导师和提炼者都看不到。

```bash
python scripts/research_eval/run.py --tasks imbalance-threshold missing-transfer \
    --condition playbook --seeds 2 --max-sprints 8 \
    --data <数据目录> --model <模型配置编号> --out scripts/research_eval/results/<名字>.jsonl
python scripts/research_eval/report.py scripts/research_eval/results/*.jsonl
```

可比较的条件：`playbook`（读研究手册）、`no-playbook`（不读）、`no-advisor`（没有导师）。
