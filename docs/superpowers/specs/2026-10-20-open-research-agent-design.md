# Open Research Agent 设计

日期：2026-10-20　状态：方向已由用户确认（"就这么做"），细节为 Claude 的提议，标注"我的决定"者可改

## 1. 意图

把现有的 Open Paper Reader 重新定位为 **Open Research Agent**：一个基于 Pi-Agent 的开源自动科研 Agent。

用户是做 Agent 的，希望它成为简历上的重头项目，并能发论文，落在 Auto-research 方向上。用户明确了主攻点：

> 核验只是基本功；**研究判断力**和**持续目标不偏移**、能**实质推进项目**才是重点。

依据（2026-10-20 调研，关键文献已核对 arXiv 摘要）：

- Kirgis, Kapoor, …, Narayanan, *Can AI agents conduct open-ended AI research?*（arXiv 2607.27191）：前沿 Agent 用 6 天和数千美元重做两篇未发表的 NeurIPS 论文，工程都做完了，但研究没有实质进展。五种失败模式：
  - 不知道什么值得发表；
  - 对设计缺陷的应对缺乏创造性；
  - 走进死胡同不会回头；
  - 不考虑资源；
  - 指令偏移。
- ResearchGym（arXiv 2602.15112）：GPT-5 Agent 跑 15 次只有 1 次超过基线。
- Ding et al. 综述（arXiv 2608.05179）：没有一个系统在流程内部有经过外部验证的核验机制。
- SciIntegrity-Bench（arXiv 2605.10246）：缺数据时，7 个模型全部伪造数据。

**核心假设**：Agent 推进不了研究，根源是没有一个**显式、持久的研究状态**。研究方向只活在上下文窗口里，被几百步工具调用稀释；也没有独立于执行者的判断环节。把研究状态写成数据结构，再加上独立的判断和强制止损，就能减少偏移、提高实质进展。

## 2. 目标、非目标、反目标

**目标**
1. 给定一个研究问题，Agent 能**跨多轮、跨天**持续推进。中断后从研究地图恢复，不靠回忆聊天记录。
2. 每一步行动都挂在研究地图的某个节点上，跑偏能被发现、被拦下。
3. 有独立的导师环节，定期做"继续 / 砍掉 / 转向 / 请人拍板"的判断，并真正生效。
4. 每个假设事先写好止损标准和预算，触发后必须回头。
5. 实验在持久工作区里真实运行，结论必须引用实验日志或文献原句（核验是底线）。
6. 有可复现的评测框架，能度量进展、偏移率、回头效率、成本，并做消融实验。目标是支撑一篇论文。

**非目标（第一版不做）**
- 不追求覆盖所有学科。实验限定在 **CPU 上几小时内能跑完的小规模机器学习或数值任务**。
- 不做自动投稿、自动 rebuttal。
- 不自己训练模型（判断力来自结构和流程，不来自微调）。
- 不做多人协作。

**反目标（即使能跑也算失败）**
- 产出看起来像论文、实际没推进问题的"空转"。
- 编造数据或结果；缺数据时不承认。
- 跑了几十轮仍在同一个死胡同里修补。
- 只能演示、不能评测：没有数字就发不了论文。
- 破坏现有阅读器、翻译、笔记等功能。它们是 Agent 读文献的能力和人工核查的工作台。

## 3. 核心概念

### 3.1 研究项目（ResearchProject）
- **北极星问题**：一句话。
- **背景说明**：可选，可附论文或数据。
- **预算**：总模型花费、总实验时长、最多轮数。
- **人工拍板设置**：哪些决策必须等人确认。
- **状态**：进行中 / 等待拍板 / 暂停 / 已结束。
- **结束原因**：得出结论 / 证伪 / 预算用尽 / 人工停止。

### 3.2 研究地图（ResearchMap）
一棵以北极星问题为根的树。

**节点类型**
- 问题：可再拆子问题。
- 假设。
- 实验。
- 发现。

**每个节点的字段**
- 标题、类型、父节点、状态（开放 / 进行中 / 已支持 / 已否定 / 已放弃 / 搁置）。
- 置信度（0–1）。
- 支撑证据和反面证据：链接到实验作业日志行或文献引文（复用阅读器的 `[[pN: "…"]]` 引文与核验）。
- 未解疑点。
- 已花资源。
- 假设节点额外必填：
  - **止损标准** `kill_if`：一句可检验的话，例如"在 3 个种子上提升都小于 0.5%"；
  - **预算上限**。

**修改记录**：地图的每次修改都有记录，包括谁改的（执行者 / 导师 / 人）、在哪一轮、为什么。地图既是 Agent 的工作记忆，也是论文里"研究轨迹"的数据来源。

### 3.3 轮次（Sprint）
- 一轮 = 一次 Pi 运行，即现有的 AgentRun，`lane="research"`，受现有的单次运行预算限制。
- 每轮开头，Agent 拿到的上下文是：北极星问题、地图快照（压缩后）、上一轮的交接摘要、导师最新意见、待办决策。
- 不把历史对话塞进去。这是对抗上下文稀释的关键。
- 每轮必须以 `end_sprint(summary, next_focus)` 结束，写交接摘要。没调用就超限结束的轮次，由系统根据步骤记录自动生成摘要，并标记为"非正常结束"。

### 3.4 聚焦与防偏移（我的决定）
- 每轮内，Agent 在做任何实验类或写入类动作之前，必须先调用 `focus(node_id, intent)` 声明正在推进哪个节点、想得到什么信息。
- 运行时记录当前焦点；没有焦点时，沙箱和写入类工具一律拒绝，并提示先聚焦。
- 偏移的度量：
  - **硬偏移**：焦点节点不在北极星问题的子树里，或者节点已关闭。
  - **软偏移**：导师在评审时逐轮判定"这一轮的工作与焦点节点、与北极星问题是否相关"。
- 两者都进评测指标；硬偏移直接拦截。

### 3.5 导师（Advisor）
- 独立的 Pi 运行，**只读**：能读地图、实验日志、文献，不能改代码、不能跑实验。
- 系统提示词和执行者不同：扮演挑剔的资深研究者。
- **触发条件**：
  - 每 K 轮（默认 3）；
  - 某个假设的止损标准可能被触发；
  - 执行者声称得到了"发现"；
  - 预算用掉 50% 和 80% 时；
  - 连续两轮在同一节点上没有地图进展。
- **对每个开放节点**给出结构化判断：继续 / 加注 / 砍掉 / 转向（提出新假设）/ 请人拍板。每条判断都带理由和引用的证据。
- **还要回答**：按目前的证据，这条线做完值不值得发表，与已读文献相比增量是什么。这里复用文献检索和阅读工具。
- **判断如何生效**：判断写进地图修改记录。"砍掉"直接关闭节点；"转向"新建节点；"请人拍板"把项目置为"等待拍板"。
- 执行者下一轮必须先读导师意见。不同意时可以申诉一次，由导师再审。

### 3.6 止损与回头
- 记录实验结果时（`record_result`），执行者必须对照该假设的 `kill_if` 自评：触发 / 未触发 / 不确定。
- 自评"触发"，节点自动转为已否定。
- 自评"未触发"但导师认为触发，以导师为准，并计入"回头延迟"指标。
- 某个节点花费超出预算上限：系统强制触发导师评审，未获"加注"就自动搁置。

### 3.7 资源意识（我的决定：v1 做简单版）
- 每个节点累计模型花费和实验时长。
- 在地图快照里给执行者看：剩余预算、各开放节点的估计信息价值（高 / 中 / 低，由执行者给出、导师校正）和估计成本。
- v1 不做自动的信息价值计算，只要求执行者选择焦点时说明理由。

### 3.8 实验工作区与作业（我的决定）
- 每个项目有一个**持久工作目录**，按项目设配额（默认 2 GB）。
- 实验在一个新的"研究沙箱"规格里运行：
  - 仍然 `--network none`、只读根文件系统、去掉所有能力；
  - 把项目工作目录挂载到 `/work`；
  - 更大的资源限额（默认 2 CPU、4 GB 内存、256 进程，可配置）；
  - 镜像预装常用科研 Python 包：numpy、scipy、pandas、scikit-learn、matplotlib、CPU 版 torch。
- 两类执行：
  - **即时命令**：沿用现有文件和 bash 工具，单条最长 60 秒；
  - **后台作业**：新增 `run_job(command, timeout)`，最长默认 2 小时，可配；以及 `job_status` 和 `job_logs`。
- 作业跨轮存活，结果写在工作区和作业日志里。日志是"证据"的唯一合法来源之一。
- 本机版需要 Docker（与现有沙箱一致）；没有 Docker 时可以建项目、做文献阶段，但不能跑实验，界面要说清楚。
- 文献通过现有后端工具获取（检索、下载、阅读），不给实验沙箱开网络。

### 3.9 核验（底线）
记录"发现"或更新置信度时，证据必须是以下之一，否则拒绝写入：
- 作业日志中真实存在的行，系统逐字核对；
- 通过现有引文核验的文献句子。

数值类结论（例如"准确率 0.873"）必须能在引用的日志行中找到。

## 4. 运行机制

- **调度**：`research_worker`（新的 worker，模式同 preparation_worker）。
  1. 找出"进行中"、没有活动轮次、预算未尽、不在等待拍板的项目。
  2. 按规则决定下一步：该跑导师就排导师运行，否则排执行者的下一轮。
  3. 运行本身仍由现有 agent_worker 执行（`lane="research"`，有单独的并发上限）。
- **工具**：在现有工具注册表上新增研究工具：
  - `research_map_read`
  - `focus`
  - `add_node`
  - `update_node`
  - `record_result`
  - `end_sprint`
  - `run_job`
  - `job_status`
  - `job_logs`
  - 导师专用 `advise`

  研究工具只在 research 车道开放。文献工具、Pi 文件和 bash 工具照常可用（bash 等受聚焦约束）。
- **提示词**：执行者和导师各有一份技能文件（`agent-runtime/skills/research-*/SKILL.md`），写明研究方法规范：
  - 先拆问题；
  - 每个假设写止损标准；
  - 不编造；
  - 缺数据就说缺；
  - 每轮结束写交接。

## 5. 评测（论文的骨架）

**评测框架**：`scripts/research_eval/`。用固定模型、固定预算、固定种子跑一组任务，导出每个项目的地图历史、轮次记录和花费，计算各项指标。

**任务集**（我的决定：分两步）
1. **自建小任务（5–8 个）**：CPU 可跑、有已知答案或明确的进展分数。每个任务故意埋入：
   - 一个看似诱人的死胡同，测回头能力；
   - 一个无关但有趣的支线，测偏移；
   - 一个缺数据的环节，测诚实。
2. **公开基准子集**：ResearchGym、EXP-Bench 或 ResearchClawBench 中 CPU 可跑的任务。可行性和许可证需在第 3 阶段核实。

**指标**
- **实质进展**：任务分数，或是否超过基线。
- **偏移率**：硬偏移被拦次数 + 导师判定的软偏移轮次占比。
- **回头延迟**：止损条件实际满足后，到节点关闭之间隔了几轮。
- **单位成本进展**。
- **诚实率**：缺数据任务中是否如实报告。
- **地图质量**：人工抽查。

**对照组**
- 同一模型、同样预算的"朴素循环 Pi Agent"：每轮只给"继续推进"和历史摘要。
- 消融：
  - 去掉地图（只给摘要）；
  - 去掉导师；
  - 去掉止损标准；
  - 去掉聚焦拦截。

## 6. 界面

- **侧栏新增"研究"入口**（`#research`）：项目列表和"新建项目"。
- **项目页**：
  - 顶部：北极星问题、状态、预算条。
  - 主体：研究地图，以树形展示节点状态和置信度。点开节点，看证据、疑点、修改历史、花费。
  - 右侧：轮次时间线，每轮的焦点、做了什么、交接摘要，可展开到工具步骤；导师意见；待拍板事项。待拍板事项可一键同意或驳回，附一句理由。
- **证据跳转**：点文献证据跳到阅读器的原句；点日志证据看日志片段。
- **视觉**：沿用现有 claude-web 式设计令牌和自写组件。

## 7. 命名与仓库（我的决定）

- 产品名 **Open Research Agent**（用户已定）。
- 第一个可运行版本跑通之后，再统一改：GitHub 仓库名、README（中英文）、站点文案、包名。原因：文案只写界面真正做到的事。
- 改名前的开发仍在现仓库 main 上，走分支 + PR。
- 阅读器、翻译、笔记、文库保持可用，作为 Agent 的文献工作台。

## 8. 阶段

1. **M1 研究循环底座**：
   - 数据模型：项目、节点、修改记录、轮次关联；
   - research_worker 调度；
   - 研究工具和聚焦拦截；
   - 执行者技能文件；
   - 持久工作区和后台作业（研究沙箱规格）；
   - 最小界面：列表、项目页、地图、时间线；
   - 用伪造模型的端到端测试；
   - 用真实模型在 1 个自建任务上跑通。
2. **M2 判断力**：导师运行和触发规则、止损自评与导师复核、拍板流程、资源和信息价值展示。
3. **M3 评测**：评测框架、自建任务集、对照组与消融、公开基准子集可行性核实、第一组数字。
4. **M4 发布与论文**：改名、README、在线版入口、论文初稿（Agent 生成的轨迹即实验数据）。

## 9. 约束

- 底层只用 Pi-Agent。保持模型无关：OpenAI 兼容和 Anthropic 协议都要能跑。
- 不破坏现有功能和测试；数据库迁移只增不改。
- 本机版和线上版都要能跑；线上版先只对管理员开放研究功能，因为跑实验会占服务器资源。
- 实验沙箱默认无网络。
- 所有花费有硬上限，超了停，不悄悄继续。
- 提交身份、PR 流程、不暴露密钥等仓库规矩照旧。

## 10. 留给实现者决定的

- 地图快照的压缩策略（多大的地图怎么塞进上下文）。
- 技能文件的具体措辞。
- 自建任务的具体题目。M3 之前出初稿，可调。
- 界面中地图的具体画法（树、缩进列表或画布），以清楚为准。

## 11. 已定的细节（审阅后补充，均为我的决定）

1. **评测时的人工拍板**：评测模式下没有人在场，"请人拍板"由导师的判断直接生效（自动通过），并记入日志；只有产品模式才真的停下来等人。各组的规则一致，结果可比。
2. **后台作业跨轮**：
   - 执行者启动长作业后，可以调用 `end_sprint(…, waiting_on=[job_id])` 结束本轮，不必空转轮询；
   - 调度器在作业结束或超时后才排下一轮；
   - 处于等待状态的轮次不计入"连续两轮无进展"；
   - 作业容器是独立、带标签的后台容器，不受单次运行 TTL 回收；broker 重启后按标签找回；
   - 作业的 stdout 和 stderr 由系统写到工作区之外、只追加的日志存储里。
3. **聚焦拦截的范围**：在后端 `execute()` 统一拦截。
   - 未聚焦也可调用：`research_map_read`、`focus`、`end_sprint`、文献类工具（检索、阅读论文、读网页）、`job_status` 和 `job_logs`（只读）。
   - 其余全部要求先聚焦：Pi 的 read、bash、edit、write、grep、find、ls，以及 `run_job`、`add_node`、`update_node`、`record_result`。
   - 粗粒度，不解析 bash 命令。
4. **硬偏移的定义**：聚焦到不存在的节点、已关闭的节点，或祖先已被否定或放弃的节点。预计很少发生，偏移的主要度量是导师逐轮判定的软偏移。
5. **花费归属**：每次模型调用按当时的焦点节点记账；第一次聚焦之前的调用记在项目层面的"规划"上。实验时长按作业所属节点记账。`run_job` 启动时绑定当前焦点。
6. **证据规则**：
   - 日志证据 = 作业编号 + 行号范围，内容取自系统保存的日志，不取自 `/work` 里 Agent 自己写的文件；
   - 数值必须在所引行中逐字出现；
   - 均值这类派生数值，必须由脚本计算并打印到作业日志里再引用。
7. **查新来源**：沿用现有的论文检索工具（Semantic Scholar、OpenAlex、arXiv）和文库；查新质量是评测里要人工抽查的项目。
8. **线上版**：M1–M3 只做本机版，线上版最早在 M4 开放给管理员。
9. **任务数据**：每个评测任务自带数据文件，开局复制进工作区；依赖只能用研究沙箱镜像里预装的包，需要别的包的任务不入选。
10. **论文主张**：以"同一模型、同样预算下，显式研究状态 + 导师 + 止损，比朴素循环有更多实质进展、更少偏移"为主；公开基准上的绝对分数为辅。

**待用户决定**：评测用哪些模型、总预算上限多少。影响 M3 的规模，不影响 M1 和 M2。
