## 1. 为什么做

纸间现在是一个功能很多的论文阅读工作台，已经开源（MIT，`Jialei-03/zhijian`），也有线上服务（papers.dougao.online）。但维护者自己读论文时用的是别人的产品 Moonlight，原因有两个：

- **纸间不够稳定**，经常出错；
- **界面不如 Moonlight 好看**。

维护者希望把它做成一个 **star 数高、容易上手、工具感强** 的开源项目。参照物有三个：

- **Moonlight**：阅读主线（导入 → 看自动导读 → 划选解释）；界面高级、丝滑、稳定，用着开心。
- **claude-web**（ypyik0669/claude-web）：设计语言（深色为主的暖色卡片界面）；「把 agent 在做什么搬到网页上」的工具感。
- **pi-web**（7.4k★）、**claudecodeui**（1.4 万★）：描述型名字 +「借一个已经很火的东西」，是它们被搜到、被转发的原因。

## 2. 它是什么

> **open-paper-reader** — Read papers with Claude Code, Codex, or Pi.

- 一个开源的论文阅读器，**主要装在自己电脑上用**。研究助手是 agent：第一版是内置的 **Pi**，下一版接入用户本机的 **Claude Code** 和 **Codex**。
- 云端版（papers.dougao.online）继续提供，作为「不想自己装」的人的便利入口，不是主线。
- 给谁：每天用 AI 编程 agent、又经常读论文的研究生和研究者（我定的）。

### 命名

- 英文名 **open-paper-reader**。GitHub 上只有 3 个零星同名小项目，npm 未被占用。命令名 `open-paper-reader`，短别名 `opr`（我定的）。
- **不再保留中文名「纸间」**。所有地方统一用英文名，中文 README 写成「open-paper-reader：开源的论文阅读器」。
- 名字和 Logo 里**不能出现** Claude、Claude Code、Anthropic，这是 Anthropic 条款的要求。文字里可以如实写「可配合 Claude Code 使用」。Codex 同理，只在说明文字里出现。
- 仓库改名（`Jialei-03/zhijian` → `Jialei-03/open-paper-reader`）、GitHub 简介和话题标签（paper-reader、claude-code、codex、pi、ai-agent、arxiv、pdf、research）放在第 5 阶段，和 README 一起做。

## 3. 目标、非目标、反目标

**目标**
1. 阅读主线做到 Moonlight 的水准：拖进论文 → 自动导读 → 划选解释 → 问助手，结论能点回原文的**那一句**。
2. 界面达到已认可样稿的水准：claude-web 式设计语言，深色为主，带浅色版。
3. 稳定：核心流程有自动化测试兜底；任何失败都有明确提示和重试办法（标准见第 9 节）。
4. 本机一条命令启动。
5. 第一版就支持中英双语界面。

**非目标（第一版不做）**
- 接入 Claude Code、Codex 的命令行（第二版做，第一版只把接口准备好，见第 5 节）。
- 在终端里直接导入或提问（CLI 第一版只负责启动）。
- 桌面安装包（Electron 或 Tauri）、手机端适配。
- 官网首页重写内容和结构（第一版只换名字、换成新的设计令牌）（我定的）。
- 第 4 节「先拿掉」的那些功能。

**反目标（做出来也算失败）**
- 不稳定、经常出错。
- 界面不如 Moonlight 好看。

## 4. 第一版的范围

**保留并重做界面**：导入（PDF、arXiv 链接）、阅读器、自动导读、划选解释和翻译、助手对话、笔记、对照翻译、**版面翻译**。

**同样保留、只是上面没单列的现有能力**（我定的）：目录、页面缩略图、文内查找、引用和链接的悬停预览、高亮和批注、导出带批注的 PDF、笔记历史版本、笔记导出、收藏和阅读状态、用量和存储统计、「允许助手修改笔记」开关。

**先拿掉**：知识图谱、发现论文、手写批注、分享链接、整篇 LaTeX 翻译、阅读测验；以及文库集合、研究方向页、Agent API 凭据页（这三项是我定的）。
- 这些功能的后端代码和数据**不删**，只是第一版的界面不露出来，以后可以接回。已有数据（线上用户的批注、笔记等）必须保留，不能因为界面不显示就丢失。
- 已有数据在新界面里怎么露出来（我定的）：
  - 已创建的分享链接和 Agent API 凭据：在设置里列出来，只能撤销，不能新建；
  - 已有的手写批注：照常显示在页面上，只读；
  - 已完成的整篇 LaTeX 翻译：还能打开看，不能新建。

## 5. 助手（agent）

**第一版：只用内置 Pi。** 沿用现在的 Pi 运行时（`agent-runtime/`）和 Python 工具层，可以连这些：
- 各家 API 密钥（OpenAI、Anthropic、DeepSeek、OpenRouter、Google 等，Pi 支持的都可以）；
- 本机模型（Ollama、LM Studio）。本机版要放开现在「只允许 HTTPS 公网地址」的限制，允许连本机地址；云端版保持现在的限制；
- **ChatGPT 账号登录**（Pi 的 openai-codex 提供方）：第一版就做，作为可选的连接方式之一。OpenAI 没有明确禁止第三方这样用，但也没有明确许可，界面上要标注「使用你自己的 ChatGPT 订阅」，只在本机版提供（有政策风险，见第 12 节）。
- **不提供「Claude 账号登录」**，即使 Pi 技术上支持。Anthropic 条款禁止第三方应用用 Free、Pro、Max 订阅凭据替用户发请求（[官方原文](https://code.claude.com/docs/en/legal-and-compliance)），而且会直接执行，已有工具被封。
- **云端版不提供任何「订阅账号登录」**，只允许用户填自己的 API 密钥，或使用部署者提供的共享模型。由服务器替用户使用订阅属于「代为中转」，不允许。

**为第二版做准备**：把纸间给 agent 用的能力，比如读某几页、全文搜索、读框选区域、看图表、读写笔记、导入 arXiv，整理成一个 **MCP 服务**。第一版的 Pi 也通过同一套能力工作（可以继续走现在的调用方式，只要能力清单只有一份）。第二版在设置里选「Claude Code / Codex / Pi」，前两者调用用户本机的原版命令行（用户用自己的订阅登录，条款允许），连上这个 MCP 服务。

**过程展示**：助手每一步做了什么都要留下记录，比如读了哪页、搜了什么、改了哪条笔记，在界面上可以展开查看（见第 6 节）。

## 6. 界面

已认可的样稿是 `mockup-reader.html`。下面是每个界面要做到的事；样稿没画到的地方，按同一套设计语言补齐。

### 6.1 首次打开：先配置模型

- 打开后，如果还没有可用的模型，先进入一个配置页：选连接方式（API 密钥、本机模型、ChatGPT 账号），填完点「测试连接」，通过后才进入首页。
- 配置页本身也要好看，这是陌生人的第一眼。它是一张居中的卡片，坐在底色上；一句话说明「助手需要一个模型来读论文」，然后是连接方式的选择（我定的）。

### 6.2 首页

- 有论文时，首页是**「继续阅读」**（最近读的几篇，点一下回到上次读到的那一页）加**「最近导入」**。
- 没有论文时，首页中间是一块大的拖放区：「把 PDF 拖进来，或粘贴 arXiv 链接」。

### 6.3 阅读器（核心）

布局（样稿 B 方案，带侧栏）：
- **左侧栏**直接坐在底色上，没有自己的底色：导入、搜索、「正在读」、文库列表、设置。可以收起。
- **中间是论文卡片**：顶部一行放标题（宋体）、页码、**阅读方式切换**；下面是 PDF。深色模式下 PDF 纸面稍微压暗，「反色阅读」开关留到以后（我定的）。
- **翻译是论文的阅读方式，不是侧边的工具**（维护者 2026-10-18 指出翻译放在右侧面板不合理）：
  - 论文卡片顶部的分段切换「原文 / 对照 / 译文」。「对照」是原文和译文逐段并排（现有的对照翻译）；「译文」是保留版式的中文 PDF（版面翻译）。
  - 切到「对照」或「译文」时还没有译文，就在原地开始翻译、显示进度，已经译好的页先显示，不跳到别处。
  - 切换旁边一个小菜单：目标语言、用哪个模型、重新翻译这一页。
  - 只想看某一段时，划选「翻译」：结果出现在选区旁边的小浮层里（几句话不占整个面板），浮层里可以「记到笔记」「复制」「问助手」。
- **划选文字**弹出浮动菜单：解释、翻译、高亮、记到笔记、问助手，每项标出快捷键（E、T、H、↵）。框选图表的菜单沿用现有的能力。
- **底部浮着一个输入框**：自动带上当前的上下文（「第 3 页」或「选中的一句」，显示成一个可以去掉的小标签），右边是模型选择和圆形发送键。
- **右侧面板**是一张卡片，顶部是分段切换：导读、助手、笔记。
  - **导读**：导入后自动生成，边生成边显示。导入后默认只自动跑导读，其他准备工作（比如对照翻译）等用户点了再做（我定的）。
  - **助手**：问答记录，每篇论文各有一份（我定的）。划选「解释」「问助手」的结果也出现在这里，和提问记录排在一起（我定的）。用户的提问显示成气泡，带引用的原文。助手的过程默认折叠成一行，例如「已处理 9 秒，读了 3 页，搜索 1 次」；点开后逐条列出每一步，每条后面标结果。回答里的**引用页码**是小标签，点击后**跳到原文里那一句或那一段，并高亮**。
  - **笔记**：这篇论文的笔记（Markdown 编辑器），下面列出这篇论文的高亮和批注，点一条跳回原文（我定的）。
- 对照翻译、版面翻译的后端沿用现有能力，界面按上面的阅读方式重做。

### 6.4 文库、设置

- **文库**：论文列表，可以搜索、按状态筛选、导入、删除。不做集合和研究方向。
- **设置**：模型（6.1 的同一套）、外观（深色、浅色、跟随系统）、语言（中文、English）、数据（存储位置、导出、用量）、已有的分享链接和凭据（只能撤销，见第 4 节）。

### 6.5 登录页和公开页面（云端版）

- 本机版不需要登录，打开就是 6.1 或首页。
- 云端版的登录页、公开页面（首页、文档）换成同一套设计语言和新名字；内容结构不动（见第 3 节非目标）（我定的）。

## 7. 视觉语言

按 claude-web 的做法定一套设计令牌（`tokens.css`），全部界面只用令牌，不写零散数值。样稿里的取值就是起点：

**结构**
- 窗口最外层是底色（shell）。侧栏直接坐在底色上；主要区域是圆角卡片（16px），卡片之间留 8px 缝。
- 浮起来的东西（菜单、输入框、对话框）**不画边线**，用「1px 阴影环 + 柔和投影」：`elev-1`、`elev-2`、`elev-composer` 三档。

**颜色**（每个主题只定义原色，边线、悬停、选中、淡底都用 `color-mix` 从文字色按比例混出来）

| 令牌 | 深色 | 浅色 |
| --- | --- | --- |
| 卡片 `bg` | `#1b1a18` | `#fefdfc` |
| 底色 `bg-1` | `#12110f` | `#f7f6f2` |
| 内嵌 `bg-2` | `#252321` | `#f0eeea` |
| 浮层 `elev` | `#272623` | `#ffffff` |
| 文字 `fg` / `fg-1` / `fg-2` / `fg-3` | `#eeedea` / `#c4c2be` / `#a5a39e` / `#868480` | `#1c1917` / `#47433f` / `#67625f` / `#7f7b77` |
| 强调色 `accent`（只做填充） | `#f5914f` | `#eb7f3b` |
| 强调文字 `accent-text` | `#f9a56e` | `#a94900` |
| 主按钮 `primary` | `#eeedea`（浅色墨） | `#1c1917`（深色墨） |

- 橙色只做点缀：「正在读」的小圆点、上下文标签、引用页码、运行中的状态。主按钮用墨色，不用橙色。
- 加一个对比度测试：两套主题里文字与底色的对比度都要达到 WCAG AA。
- 这套取值改编自 claude-web（MIT），在 NOTICE 里注明（我定的）。

**字体**
- 界面用 Inter；代码和工具名用 JetBrains Mono。
- 论文标题、页面大标题用宋体（Songti SC / 思源宋体）。
- 字体随包发布，不依赖外网字体服务。宋体如果需要随包，只裁出用到的字（我定的）。
- 中文只用 400 和 600 两个字重；字号用一套整数阶梯。

**形状**：圆角阶梯 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24 / 胶囊，按元素大小选；内圆角等于外圆角减去内边距。

**动效**：只动位移、透明度、颜色；一套固定的时长和缓动；只有眼前实时发生的事才播进场动画；遵守系统的「减少动态效果」。

**图标**：线性图标，形状来自 Lucide，线宽按尺寸定。

## 8. 技术做法

- **前端**：继续用 React + TypeScript + Vite。**去掉 shadcn/ui、Radix、Tailwind、class-variance-authority、tailwind-merge、cmdk、sonner**，菜单、对话框、提示、分段控件、侧栏等组件全部自己写，键盘操作和无障碍属性不能少。PDF.js（渲染 PDF）和 TipTap（笔记编辑器）这类「引擎」保留，界面外观自己做。图标可以继续用 lucide-react，也可以改成构建时生成（我定的：先用 lucide-react）。
- 这是**界面层的重写**，不是在旧组件上修补。旧界面代码在新界面覆盖到之后删除，不要新旧并存的开关（我定的）。
- **后端**：沿用现有的 Python 服务和数据模型，接口尽量不改。本机版默认用 SQLite，数据放在用户目录下的一个固定文件夹（例如 `~/.open-paper-reader/`）（我定的）。
- **启动命令**：`open-paper-reader`（别名 `opr`），启动本机服务并自动打开浏览器。安装方式以「一条命令」为目标，例如 `uvx open-paper-reader`；Pi 运行时需要 Node.js，启动时要检查依赖，缺什么就明确说缺什么、怎么装（具体打包方式交给实现者）。
- **支持的系统**：第一版就支持 macOS、Linux 和 Windows（原生 Windows，不要求 WSL）。路径、数据目录、进程启动和停止、版面翻译的安装都要按三个系统分别处理和测试。
- **版面翻译**：改成按需安装。第一次使用时，由用户点「安装」，把 BabelDOC 装进一个单独的环境，不再依赖 Docker。BabelDOC 是 AGPL，不打包进主程序。
- **助手的代码沙箱**（Docker）：本机版不要求 Docker。没有 Docker 时，这些工具明确提示不可用，不影响读论文。
- **云端版**：同一套代码部署，多出登录和账户隔离。
- **中英双语**：所有界面文字都走一份文案表，不在组件里写死。默认跟随浏览器语言，设置里可以切换。助手、导读的输出语言跟随界面语言，也可以单独设置。翻译的目标语言可以设置：第一版提供中文和英文，默认等于界面语言（我定的）。

## 9. 「稳定」的验收标准

维护者说的「不稳定」四种都有：导读或解释生成失败、导入失败、界面报错或卡顿，以及说不清的整体不可靠。所以每一种都要有对应的测试：

- **生成失败**：用本机的假模型故意制造超时、半路断开、返回格式错误、限流，测出界面都能给出提示和重试，已生成的部分不丢；生成不会无限转圈，超过时限一定结束并说明原因。
- **导入失败**：一组「难导入」的样本论文（扫描版、加密、超大、带奇怪字体、arXiv 只有 HTML 或版本号不对等），每一篇要么导入成功，要么告诉用户为什么失败。
- **界面报错或卡顿**：任何组件出错都不白屏，只影响出错的那一块；翻页、划选、切换面板有性能预算（具体数值由实现者测出基线后定），CI 里超出预算就失败。
- **整体不可靠**：CI 里把核心流程连着反复跑多遍，同时随机注入模型和网络故障，一次失败都不允许；修过的每个问题都补一条回归测试。

具体要求：

1. 这些核心流程都有浏览器自动化测试，深色、浅色和中、英各跑一遍关键截图：
   - 首次配置模型；
   - 导入 PDF；
   - 导入 arXiv；
   - 自动导读生成；
   - 划选解释；
   - 划选翻译；
   - 问助手后点引用，跳到原文那一句；
   - 写笔记并保存；
   - 对照翻译；
   - 版面翻译（安装后）。
2. 页面上不出现未处理的报错。每个失败都告诉用户「发生了什么、怎么办」，能重试的给出重试按钮。
3. 模型或网络出错时，已经完成的部分保留。例如导读生成到一半失败，已生成的段落不丢。
4. 现有的后端测试和 CI 全部通过。
5. 在一台没装过的电脑上，按 README 能一条命令装好、跑起来。macOS、Linux、Windows 三个系统都在 CI 里跑一遍「安装、启动、导入一篇论文、打开阅读器」（第 4 阶段起验证）。

## 10. 分阶段

建议的顺序。每个阶段单独开分支、走 PR、CI 全绿后合并，可以单独上线云端版：

1. **地基**：设计令牌、基础组件（按钮、输入框、菜单、对话框、分段控件、提示、侧栏、卡片外壳）、深色和浅色主题、文案表框架；第 9 节要用的故障注入假模型和「难导入」样本集。
2. **阅读器**：论文卡片（含「原文 / 对照 / 译文」阅读方式）、划选菜单和划选翻译浮层、浮动输入框、右侧面板（导读、助手、笔记）、引用跳到原文那一句。
3. **其他界面**：首次配置、首页、文库、设置；拿掉第 4 节列出的那些界面入口。
4. **本机版**：启动命令（macOS、Linux、Windows）、SQLite 默认配置、本机模型地址放开、ChatGPT 账号登录、版面翻译按需安装、没有 Docker 时的降级、三个系统的安装测试进 CI。
5. **英文与发布**：英文文案全部补齐、改名（仓库、页面标题、README）、README 开头的动图、发布 v0.2.0。

## 11. 约束

- 仓库规则：每个改动走分支和 PR，CI 全绿后再合并；提交作者用维护者本人的身份，不署名 Claude。
- 线上已有用户的数据必须完整保留，数据库迁移只能新增，不能破坏。
- 许可证：BabelDOC 是 AGPL，必须保持隔离；借用 claude-web（MIT）的令牌，要在 NOTICE 里注明。
- 商标：名字和 Logo 不用 Claude、Anthropic、OpenAI 的名字。
- 公开页面和登录页的首屏脚本保持在现有预算内（不到 500 KB）。

## 12. 风险

- **ChatGPT 账号登录**依赖 OpenAI 的态度，以后可能被限制。这是可选项，不能是唯一的连接方式。
- **Node.js 依赖**可能让「一条命令启动」变复杂，打包时要实测。
- **原生 Windows** 的坑最多：路径和换行、子进程的启动和结束、杀毒软件拦截、BabelDOC 的依赖。第 4 阶段要留出专门的时间，CI 里要有 Windows 机器。
- **BabelDOC 按需安装**体积可能很大（模型和字体），要显示进度，可以取消。
- **重写范围大**，所以按阶段推进，每个阶段都要可用、可上线。

## 13. 留给实现者决定的

- 组件的具体拆分、文件结构、状态管理方式。
- 图标的引入方式。
- 安装和打包的具体方案（uv、pipx、npm 包装都可以），只要满足「一条命令」和「依赖缺失时说清楚」。
- MCP 服务的具体接口形式。
- 样稿没有画到的细节，比如空状态、加载状态、错误状态，按第 7 节的设计语言补齐。
