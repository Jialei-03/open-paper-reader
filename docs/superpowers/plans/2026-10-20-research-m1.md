# Open Research Agent M1：研究循环底座 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给定一个研究问题，Agent 维护持久的研究地图，跨多轮推进；每步必须聚焦到地图节点；实验在持久工作区和后台作业里真实运行；结论必须引用系统日志或文献原句；本机版可端到端跑通。

**Architecture:** 新增研究项目、地图节点、修改记录、轮次和作业五张表。research_worker 为每个项目排"轮次"，每轮是一个 `lane="research"` 的 AgentRun，交给现有 agent_worker 执行。研究运行不带会话历史，系统提示词来自技能文件，上下文是地图快照。研究工具挂在现有工具注册表上，由 `execute()` 统一做聚焦拦截。实验在本机 Docker 的"研究沙箱"里运行，项目工作目录挂载到 `/work`，作业日志由系统保存在工作区之外。

**Tech Stack:** FastAPI + SQLAlchemy + Alembic（SQLite/Postgres）、Pi runner（Node）、Docker CLI、React 19 + CSS Modules + 自写 ui kit、pytest、vitest。

**Spec:** `docs/superpowers/specs/2026-10-20-open-research-agent-design.md`（第 3、4、6、8、11 节为 M1 依据；导师和评测是 M2/M3，不在本计划内）

## Global Constraints

- 数据库迁移只增不改：新迁移 `0027`，`down_revision = "0026"`。
- M1 只做本机版：研究接口在非 local 模式下，非管理员返回 403；研究沙箱只走本机 Docker CLI，不改线上 broker。
- 实验沙箱：`--network none`、`--read-only` 根文件系统、`--cap-drop ALL`、`--security-opt no-new-privileges`、默认 `--cpus 2 --memory 4g --pids-limit 256`；`/work` 挂载项目工作目录，`/tmp` 用 tmpfs。
- 即时命令最长 60 秒（沿用 sandbox-tools.mjs）；后台作业默认超时 7200 秒，上限可由配置 `RESEARCH_JOB_MAX_SECONDS` 调整。
- 项目工作区配额默认 2 GB（`RESEARCH_WORKSPACE_BYTES`）；超出时 `run_job` 拒绝启动。
- 文字说读者的话；界面文字中英双语，走 i18n catalog（`npm run check` 校验）。

- 不破坏现有功能：`pytest backend/tests` 中已有测试、`vitest`、`npm run check` 全部保持通过。

## Review Focus

1. 模型在没有先 `focus` 的情况下直接调用 bash：必须拒绝，并给出"先调用 focus"的明确提示，不能悄悄执行。→ Task 4 测试。
2. 轮次超过单次运行限制、没有调用 `end_sprint` 就结束：项目不能卡死。轮次要标记为"非正常结束"并自动生成交接摘要，调度器能排下一轮。→ Task 7 测试。
3. 作业运行中 backend 重启：重启后按容器标签找回作业，结束后仍能收集日志，不能留下永远"运行中"的作业。→ Task 5 测试。
4. 证据中的数字在日志里不存在（模型编造）：`record_result` 必须拒绝，节点状态不变。→ Task 6 测试。
5. 本机没有 Docker 或 Docker 没启动：建项目和文献类工具照常可用；实验类工具返回可读的错误；界面显示"需要 Docker"。不能崩溃，也不能无限重试。→ Task 5、Task 9 测试。
