# Open Research Agent M2：研究判断力 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 给研究循环加上独立的判断：导师 Agent 在固定时机审视研究地图，对每个开放节点给出"继续 / 加注 / 砍掉 / 转向 / 请人拍板"，判断自动生效；同时把偏移、回头延迟和进展记录成可度量的数据。

**Architecture:** 导师是一个 `role="advisor"` 的研究轮次，即一次 AgentRun。它只读地图、日志和文献，唯一的写工具是 `advise`。调度器按触发规则决定下一轮是执行者还是导师。`advise` 的结论由系统应用到地图上：砍掉的节点关闭，转向时新建节点，请人拍板时项目进入"等待"。执行者下一轮的 brief 里带上导师的最新意见。新增 `research_metrics.py`，从事件流计算各项指标。

**Spec:** `docs/superpowers/specs/2026-10-20-open-research-agent-design.md` 第 3.5–3.7 节、第 11 节第 1 条。

## Global Constraints

- 只增不改的迁移：如需新列，用 `0028`。
- 评测模式（项目 `budget.auto_decide == true`）下，"请人拍板"直接按导师意见执行，并记录 `auto_decided` 事件。
- 导师不能运行代码、不能写文件、不能改地图（除 `advise` 外的写工具一律拒绝）。
- 其余同 M1 的全局约束。

## Review Focus

1. 导师给的节点编号不存在或已关闭：该条判断跳过并记录，其余判断照常生效，不能整体失败。
2. 导师轮没调用 `advise` 就结束：调度器不能卡住，下一轮照常排执行者，并记录 `advisor_silent`。
3. 导师判断"砍掉"，而执行者当前正聚焦在这个节点：执行者下一次动作被拦截（`closed_focus`），brief 中说明原因。
4. 等待拍板的项目：不排任何新轮次；拍板后立即恢复。
5. 指标计算遇到空项目或只有一轮的项目时，结果为 0 或 null，不报错。

### Task 1: 导师角色、`advise` 工具与应用逻辑

**Files:** Create `backend/research_advice.py`、`agent-runtime/skills/research-advisor/SKILL.md`；Modify `backend/research_tools.py`（`advise` 工具，导师只读拦截）；Test `backend/tests/test_research_advice.py`

**Interfaces:**
- `advise` 参数：
  - `verdicts`：1–30 条，每条 `{node_id, verdict ∈ {continue, invest, kill, pivot, ask_human}, reason ≤1000, new_hypothesis?: {title, kill_if}}`；
  - `drift`：每轮一条 `{sprint_number, on_track: bool, note ≤300}`；
  - `assessment ≤2000`：值不值得发表、与文献比的增量；
  - `conclude?: {status ∈ {concluded, refuted}, summary}`：导师认为北极星问题已经得到回答时使用。
- `research_advice.apply(d, project, sprint, args) -> dict`，按 verdict 处理：
  - `kill`：节点状态置为 abandoned，理由前缀"导师："；
  - `pivot`：在被转向节点的父节点下新建假设（kill_if 必填），原节点 parked；
  - `invest`：在节点的 doubts 里写一条"导师建议加注"；
  - `ask_human`：在非自动模式下，项目状态置为 waiting，并写一条 `decision_requested` 事件，detail 为 `{node_id, verdict, reason}`；
  - 每条 verdict 写一个 `advice` 事件；每条 drift 写一个 `drift_judged` 事件；
  - `conclude`：项目状态置为 finished，end_reason 取 conclude 的状态；
  - 不合法的节点：跳过，并写 `advice_skipped` 事件。
- 导师角色下，`gate` 只放行 `FOCUS_FREE ∪ {"advise"}`，其余一律拒绝，提示"导师只做判断，不动手"。

### Task 2: 触发规则与调度

**Files:** Modify `backend/research_worker.py`、`backend/research_brief.py`（`advisor_brief`，以及执行者 brief 中的"导师意见"一节）、`backend/agent_worker.py`（按角色选技能文件和工具）；Test `backend/tests/test_research_worker.py` 追加

**Interfaces:**
- `next_role(d, project) -> "executor" | "advisor"`。满足以下任一条件时安排导师，否则安排执行者：
  - 距上次导师已过 `ADVISOR_EVERY = 3` 个执行者轮；
  - 上一执行者轮写了 `record_result`，且 `kill_triggered ∈ {yes, unsure}`；
  - 上一执行者轮新增了 `finding` 节点；
  - 项目花费首次跨过 50% 或 80%（按 sprints 和 tokens 中较高的比例）；
  - 连续两个执行者轮没有地图进展：没有 add_node、update_node 或 record_result 事件，且两轮都不在等待作业。
- 导师轮的 `runtime.research.role = "advisor"`；工具 = FOCUS_FREE 中的研究工具和文献工具 + `advise`；系统提示词来自 research-advisor 技能文件。
- 导师轮结束时如果没调用 advise：记录 `advisor_silent` 事件，下一轮排执行者。
- `waiting` 状态的项目不排任何新轮次。
- 执行者 brief 新增"导师意见（第 N 轮）"一节，内容是 assessment 和各条 verdict。

### Task 4: 研究过程指标

**Files:** Create `backend/research_metrics.py`、`GET /projects/{id}/metrics`；Test `backend/tests/test_research_metrics.py`

**Interfaces:** `metrics(d, project) -> dict`，各字段：
- `sprints`：执行者轮数和导师轮数；
- `hard_drift_blocks`：drift_blocked 事件数；
- `soft_drift_rate`：被导师判为 off-track 的执行者轮占已判定轮数的比例；
- `backtrack_latency`：每个被否定或放弃的假设，从首条 kill_triggered ∈ {yes, unsure} 或导师 kill 起，到节点关闭为止的执行者轮数，取均值；
- `abnormal_rate`：未正常交接的轮次比例；
- `evidence_count`；
- `tokens_per_supported`：每个"已支持"节点平均花费的 tokens。
