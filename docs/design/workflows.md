# 设计：工作流

用户说过要把「读论文 → 找灵感 → 做研究 → 写文章」串起来。工作流就是把一段研究分成有顺序的几步，每步有自己的目标和产出，上一步的产出交给下一步。现在的「定题 → 实验 → 结论 → 复盘」就是一个固定的工作流，这次把它一般化。

## 概念
- **工作流**：名称 + 有序的步骤列表。内置几个，用户可以复制后修改，也可以新建。
- **步骤**：名称、类型、要做什么（给 agent 的指示）、产出（项目仓库里的文件路径，或一张卡片）、完成后是否要你确认才继续。
- **步骤类型**：
  - `agent`：一个 agent 在研究的 worktree 里工作，可以用文件、命令、文献工具，以及只读的项目工具；完成时调用 `finish_step(summary, outputs)`。
  - `plan`：现在的定题：对话，写计划卡片，你批准。
  - `experiment`：现在的实验循环（执行者、导师、轮次、作业），直到提出结论。
  - `review`：只读的导师评审上一步的产出，给出通过或修改意见；不通过就退回上一步，最多 N 次。
- 每步的产出写进项目仓库：每步结束时提交一次（沿用每轮的检查点提交）。下一步的简报里有上一步的摘要和产出文件列表。

## 内置工作流
1. **研究**（默认，就是现在的）：定题（plan）→ 实验（experiment）→ 结论（你确认）→ 复盘。
2. **文献综述**：收集论文（agent：从资料库和检索里找，写 `review/sources.md`）→ 精读要点（agent：每篇的问题、方法、结果、局限，写 `review/notes.md`）→ 综述成文（agent：写 `review/review.md`）→ 评审（review）。
3. **复现一篇论文**：选定论文（plan：说清复现哪个结果、怎么算成功）→ 复现实验（experiment）→ 对比报告（agent：写 `reproduction.md`，对照论文数字）。
4. **写论文**：汇总项目结论（agent：读项目记忆和各研究的结论，写 `paper/outline.md`）→ 写草稿（agent：`paper/draft.md`，或 LaTeX 的 `paper/main.tex`）→ 自审（review）→ 你确认。
5. **从读到写**：文献综述 → 找方向（agent：从综述里提出 3–5 个可做的问题，写成看板上的想法卡片，你选一个）→ 研究（以子研究的方式派出，用「研究」工作流）→ 写论文。

## 界面
- 新研究页：输入框底栏多一个「工作流」选择（下拉，默认「研究」）。选了别的工作流，第一句话就是这个工作流的输入。
- 对话页：对话流里每步开始和结束各一行分隔（「精读要点 · 完成」），产出文件以卡片出现（点开在右侧看内容）。需要你确认的步骤，结束时出一张卡片：「继续」「重做这一步」。
- 右侧面板：多一个「工作流」部分，列出各步和状态（完成 / 进行中 / 等你 / 未开始），点一步跳到对话里的那个位置。
- 自定义 → 技能 → 工作流：列出内置和自己的工作流；内置的只能查看和复制；自己的可以编辑：步骤列表（增删、拖动排序），每步填名称、类型、指示、产出、是否要确认。没有任何说明文字。
- 定时任务可以选择用哪个工作流开新对话（比如每周一用「文献综述」跟踪一个方向）。

## 后端
- 工作流定义：内置的放在代码里，用户的存数据库（JSON），版本化；研究开始时把用到的工作流快照存进研究（之后改工作流不影响进行中的研究）。
- 研究记录当前步骤和每步的状态、开始结束时间、产出、摘要。
- 现有的 stage（scoping/experiments/conclusion/retrospective/done）要和新机制兼容：老研究视为「研究」工作流，数据不迁移也能正常显示。
- worker：当前步骤是 agent / review 时，按步骤启动运行；plan 和 experiment 交给现有机制，结束条件和现在一样。
- 工具：`finish_step(summary, outputs[])`，只在 agent 步骤可用；review 步骤用 `review_step(pass, notes)`。
- 预算：每步可设轮数上限，默认 agent 步骤 3 轮。
