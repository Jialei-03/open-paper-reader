# 设计：研究团队（agent team）

用户的定位：ORA 是一支自动做研究的团队。我是负责人，团队里是我自定义的 agent；我像在 Slack 里一样和他们交流，用工作流规定他们怎么配合。画布、留言板、工作流不拆成几个独立功能，而是同一个团队的几种看法。

参考：Slack（频道、私信、线程、@、成员）；Claude Code、Codex、MiniMax Code 的消息投递（agent 忙时可以排队，也可以立即插话）；黑板架构和 GPTSwarm 式的「agent 图」（docs/design 里 workflows 的研究背景）。

## 1. 概念：只有这几样

| 概念 | 是什么 | 对应现在的 |
|---|---|---|
| 团队 | 一个项目。有成员、频道、工作流、仓库 | 项目（ResearchWorkspace） |
| 成员 | 我，加上若干 agent。每个 agent 有名字、头像、角色说明、模型、工具、能用的机器、预算 | 执行者、导师、提炼者等固定角色，变成可配置的成员 |
| 频道 | 团队里的公共讨论区。消息就是黑板：所有成员都能读 | 研究对话、项目主会话、通报 |
| 私信 | 我和某个 agent 一对一 | 项目对话 |
| 线程 | 某条消息下面的回复，一件具体的事在里面推进（一项研究、一次实验、一篇稿子） | 一项研究 |
| 工作流 | 团队的规矩：谁在什么时候接什么话、交给谁、什么时候停下来等我 | 研究阶段机制、定时任务、上次的线性工作流 |

研究地图、计划、结论、实验、文件变更，都是线程里的消息或者置顶在线程上的卡片，不再是独立页面。

## 2. 交流：仿 Slack

- 左侧栏：团队名；频道（`#综述`、`#实验`、`#写作`、`#闲聊`，可增删）；私信（每个 agent 一个，带在线状态：空闲、工作中、等你）；下面是「线程」「提及我的」两个入口。
- 消息：
  - `@某人` 叫醒某个 agent 来回应；不 @ 的消息由工作流决定谁接。
  - agent 之间也可以 @ 对方，这就是协作：执行者跑完实验 @ 导师评审，导师 @ 写手更新稿子。
  - 每条 agent 消息可以展开看它的工作过程（用时、步骤、改了哪些文件），和现在对话里的轮次折叠一样。
  - 消息可以开线程；一项研究就是一个线程，线程顶部置顶计划卡片和结论卡片。
- 我发给一个正在工作的 agent 时，输入框给两个选择（参考 Claude Code 和 Codex）：
  - **排队**（默认，回车）：等它这一步做完再看到；
  - **立即发送**（⌘回车）：插进它正在进行的这一轮，它马上看到并调整（Pi 的 steer，运行器已经支持）。
  - 排队中的消息显示在输入框上方，可以改、可以撤回、可以改成立即发送。
- 后台作业（实验）跑完，结果作为一条系统消息发回它所在的线程，并叫醒发起它的 agent；长作业不阻塞团队里其他人。

## 3. 成员：自定义 agent

- 在团队设置里「添加成员」：名字、头像（自动生成）、一段角色说明（就是它的 skill）、模型、工具权限（读文献、改文件、跑实验、上 SSH 机器、只读）、预算。
- 内置几个可以直接加的：导师、执行者、文献员、评审、写手、提炼者（来自现在的 skills）。
- 每个成员有自己的私信记录和工作记录；成员之间共享频道和团队仓库。

## 4. 工作流：团队的规矩

- 工作流就是一组「当……时，谁做什么」的规则：
  - 当 `#实验` 里出现实验结果 → 导师评审，评审不通过 → 退回执行者，最多 3 次；
  - 当我在线程里批准计划 → 执行者开始；
  - 当导师提出结论 → 停下来等我；
  - 每天 9:00 → 文献员把新论文发到 `#综述`（就是现在的定时任务）。
- 两种看法，同一份数据：
  - **列表**：一条条规则，适合改细节；
  - **画布**：成员是节点，规则是连线（交接、评审、订阅频道、等我），频道是一块大节点（黑板）。拖线就是加规则。运行时节点上显示谁在工作、谁在等。
- 内置几套：现在的研究流程（执行者 ↔ 导师，研究地图作黑板）、文献综述、复现、写论文、从读到写。上次做的线性工作流改写成这里的模板。
- 同一个问题可以换一套工作流再跑一遍，在团队里并排比较结果、花费、时间：这就是「探索 agent 的协作方式」。

## 5. 运行机制（后端）

- 每条进入频道或线程的消息都是一个事件。调度器按工作流规则和 @ 决定叫醒谁；一个 agent 被叫醒就是一次 Pi 运行，读这条消息、它所在线程的上下文（压缩过的）和团队黑板（频道摘要、研究地图），用自己的工具干活，把结果作为消息发回。
- 同一个 agent 同时只跑一件事，后来的消息排队；我选「立即发送」时走 steer。
- 预算按成员和团队两级计；工作流里的「最多 N 次」防止 agent 之间无限互相 @。
- 现有的研究（阶段、轮次、地图、作业、检查点提交、分叉合并）全部保留，作为「研究线程」的内部机制；老数据不迁移也能显示成团队里的线程。

## 6. 分步

1. 团队和消息：频道、私信、线程、@、排队和立即发送；现有研究显示成线程；内置成员。
2. 自定义成员。
3. 工作流规则引擎和列表视图；把现在的研究流程改写成默认工作流。
4. 画布视图和运行时状态。
5. 并排比较不同工作流。
