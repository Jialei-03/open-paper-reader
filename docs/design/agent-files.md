# 设计：成员就是文件（标准的自定义 agent）

原则：ORA 只提供工具，不规定用法。@ 几个人、谁跟谁接力、一次叫醒多少，都由用户和他写的工作流决定；系统只负责把用户的意图执行清楚，并提供预算这类用户可调的护栏。

## 成员的定义是一个 Markdown 文件
参照 Claude Code 的自定义 subagent（`.claude/agents/*.md`，YAML 头 + 正文，opencode 等工具也用同样的写法）：

```markdown
---
name: 文献员
description: 找论文、核对出处、写一句话总结。需要文献时找它。
model: MiniMax-M3.1-Flash        # 可省略：用团队默认模型
tools: [literature, files, web]   # 可用：literature、files、shell、experiments、web、project；省略 = 角色默认
machines: [host]                  # 可省略
channels: ["#综述"]               # 订阅的频道，可省略
color: amber                      # 头像颜色，可省略
---

你是这个团队的文献员。……（正文就是它的说明，写法和 Claude Code 的 subagent 一样）
```

- **位置**：
  - 团队成员放在项目仓库的 `.ora/agents/<名字>.md`，跟着项目走、进 git、有历史、可以在任何编辑器里改；
  - 个人的成员库放在数据目录的 `agents/`，从库里加入团队就是把文件复制进项目，之后各自独立；改库里的文件时，询问是否同步到用了它的团队；
  - 内置成员（导师、执行者、文献员、评审、写手、提炼者）是随 ORA 发布的文件，第一次建团队时复制进项目，用户可以随便改；想恢复，可以从内置的那份重新复制。
- **团队共享说明**：项目仓库根目录的 `AGENTS.md`（Codex、Claude Code 等工具通用的约定），所有成员都读，替代现在的 `PROJECT.md`（老项目自动改名，内容不变）。
- **界面就是编辑这个文件**：成员页左边是表单（名字、说明、模型、工具、机器、频道、预算、颜色），右边是正文的 Markdown 编辑器，保存即写文件并提交。也可以切到「源文件」直接编辑整份文件。文件在仓库里被外部改动时，界面自动读到新内容；格式写错时显示具体哪一行，并保留上一份有效的定义继续用。
- **导入**：可以导入 Claude Code 的 `.claude/agents/*.md`（字段相同，tools 名称映射到 ORA 的工具组）和 Codex 的 agent 角色 `.toml`（`description`、`developer_instructions` 对应过来）。不认识的字段原样保留在文件里。
- 数据库只记运行状态（成员 id ↔ 文件路径、状态、花费、消息），定义以文件为准。

## 叫醒和护栏（修正上一版的限制）
- 消息里 @ 了谁就叫醒谁，几个都行，同时开工；顺序和分工由用户在消息里自己写，或者由工作流规则决定。系统不改写用户的意图。
- agent 叫别人做事，用发消息工具的 `to` 写明成员（参照 Claude Code agent team 的 SendMessage），几个都行；agent 正文里的 @ 只是提到，不叫醒任何人。实测里模型经常顺手写「沿用 @导师 的口径」「要不要请 @评审」，按文字 @ 叫醒会让整条线程连锁扩散。
- 成员默认没有任何预算上限（轮数、时长、token 都不限），表单里也不设这些项。文件里自己写了 `budget`（`turns`、`minutes`、`tokens`、`total_tokens`）才生效。
- 用户可选的护栏：团队设置里的团队 token、同时工作的成员数（默认不限）；线程里 agent 之间的连续接力上限，默认 12，可改可关。
- 正在做或排队中的成员，消息上有「停止」。
- 达到用户设置的上限时，在线程里发一条说明，并通知我。
- 「停下来等我」只在两种情况发生：工作流规则里写了 `wait_for_owner`，或者 agent 自己判断需要我决定（用一个工具明确提出问题）。导师不自动被限制。
