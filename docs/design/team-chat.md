# 设计：团队聊天参照飞书

研究团队的聊天不再参照 Slack（用户 2026-10-24 确认：频道与私信合并为一个按最近活动排序的列表；我的消息靠右、浅强调色气泡），参照飞书的消息页和 Codex / MiniMax 的产出面板。界面只有标签，不加说明文字。

## 三栏
- 左：会话列表（项目侧栏里的团队部分）
  - 顶部一排常用成员头像（点开私信）。
  - 「线程」「提及我的」两个入口，带未读数（红色数字徽标）。
  - 「消息」：频道和私信一个列表，按最近活动排序，可置顶。每行：头像（频道用 # 方块，成员用彩色圆头像 + 状态点），名字，右上时间，第二行最后一条消息预览「作者：内容」，有未读时右下红色数字；成员工作中时第二行显示「工作中…」（强调色）。
- 中：聊天
  - 标题栏：名字，人数「人 1 · 智能体 6」，右侧图标：搜索、文件、侧边面板开关。
  - 我的消息靠右，浅强调色气泡；成员消息靠左：彩色圆头像，名字 +「智能体」标签，浅灰卡片气泡。
  - 卡片里：工具调用折叠成一行（「查论文 · 读网页 ×2」，点开看过程），正文，产出文件为文件卡片（图标、文件名、打开）。
  - 卡片下一行：交接去向「交给 写手」、模型、时间、「N 条回复」（强调色链接）；悬停出现复制、回复、停止。
  - 排队中：一行「头像 名字 排队中」。
  - 私信空状态：成员名片（头像、名字、简介、模型、工具）。
  - 输入框：占位「发送给 <会话名>」，右侧 @、附件、发送；成员工作中时出现「立即发送」。
- 右：侧边面板（可收起，记住开关）
  - 进度：当前会话里工作中 / 排队中的成员。
  - 交付物：本会话产出的文件，点开预览。
  - 来源：引用过的论文。

## 视觉
- 层级：页面底色 < 卡片；列表行悬停与选中用现有 ghost hover / selected 填充。
- 文字对比：正文用主文字色，次要信息用次级色，只有时间等元数据用最弱色。
- 头像颜色来自 agent 文件的 color，频道头像统一中性色。
- 不新增尺寸变量，沿用 frontend/src/ui/tokens.css。

## 反应、转发与引用
- 消息悬停工具条提供固定 👍、👎、✅，消息下方计数可切换自己的反应。研究者给成员的 👍/👎 作为最近 10 条反馈随下次工作上下文传入；✅ 不进入反馈。不修改成员文件，不生成动态，不向成员开放反应工具。
- 「更多操作 → 转发」选择频道或成员私信，可附留言。目标消息保存作者、时间、摘录和原消息入口；转给成员沿用私信唤醒与排队规则。
- 选中消息正文可「引用」，输入框上方显示引用块。发送后作为原线程的回复保存，成员在唤醒和立即发送时均能看到引用原文。
## 同事状态、名片与离开摘要
- 私信顶栏、会话预览和头像名片共用成员状态：运行中显示最新工具步骤的人话描述与累计已用时，没有步骤时显示「思考中」；排队显示「前面 N 个」。已有运行按当前用户的运行队列计数，尚未创建运行的投递按团队收件队列计数；数量不构成执行上限。
- 头像悬停、点头像或消息作者名打开名片：文件中的简介、模型、工具、状态、最近三个未删除的产出文件，以及「发消息」「查看详情」。名片复用 Floating，文件复用预览入口。
- 打开或重新聚焦频道/私信时，在标记已读前请求 `GET /research/workspaces/{id}/team/channels/{channel_id}/summary`。默认聚合频道 `read_at` 至本次服务端时间，也支持带时区的 `since`、`through`；范围为 `(since, through]`，包含线程和原生/历史运行的完成事件。
- 至少五条新消息或一次成员完成工作时，在第一条未读（在线程内则在根消息）前显示「你离开后」。按事件归并完成次数、文件、交接、未解决的决策和失败，不调用模型；可收起、打开文件、跳到未读。删除文件只显示标签。
- 摘要在本次查看期间保留，不随轮询标记已读而消失。消息接口返回服务端 `read_through`，空会话也能记住看过的时间；只读线程不推进整个频道的时间。复用现有字段，无数据库迁移。
## 置顶、稍后与频道同步
- 消息「更多操作」提供「置顶到频道 / 取消置顶」和「稍后查看」，系统消息与线程回复也适用。频道顶栏显示置顶数，侧面板「置顶」列出摘录和文件，点击定位原消息。置顶由研究者管理，成员可读；普通团队运行和原生研究轮次的简报均带本频道最近最多 10 条置顶摘录，频道内的置顶数量不限。
- 「动态」的筛选组增加「稍后」，保留研究者标记的消息，可完成、恢复和移除；私信与原生研究根消息同样支持。标记和完成状态只归研究者，不进入成员工具或上下文。
- 频道线程输入框下方可勾选「同时发到 #频道」。原回复保留在线程中，频道新增带「来自线程」入口的普通消息，点击定位原回复；正文与文件跟随原回复更新。`team_send_message` 支持 `also_channel=true`，成员自行决定何时同步结论；同步副本不重复触发路由或唤醒。
- `0052_team_message_marks.py` 保存共享置顶及研究者私有标记，按消息、类型与归属去重；兼容原生研究及旧会话的虚拟消息 ID。
## 暂停成员与提醒
- 成员详情和私信名片提供「暂停 / 恢复」，会话列表与名片显示暂停状态。暂停只阻止新唤醒：研究者的提及保留通知，成员工具拒绝唤醒，已有队列等恢复，运行中的工作继续；停止仍使用消息上的「停止」。工作流跳过暂停成员，并写入动态。
- 消息「更多操作 → 提醒我…」提供 20 分钟后、1 小时后、明早 9 点及自定义时间，按研究者本地时间选择。提醒是研究者私有的一次性计划，复用 schedules 调度循环，离线后补发，不启动成员、不进入定时任务列表，也不进入成员上下文。
- 到点的动态包含原消息摘录，点击定位原消息；只计动态未读。桌面版在后台轮询提醒并发系统通知，同一进程内去重，点击打开动态；浏览器不发系统通知。
